# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Git Extensions is a Windows-only WinForms GUI for git (.NET 10 `net10.0-windows`, C# 14). It shells out to the real `git` executable. The solution is `GitExtensions.slnx`.

## Commands

```shell
git submodule update --init --recursive   # required after clone / new worktree (externals/)
dotnet build /v:q                         # whole solution; TreatWarningsAsErrors is on, so StyleCop/analyzer violations fail the build
dotnet test                               # whole suite
dotnet test tests/app/UnitTests/GitCommands.Tests --filter "FullyQualifiedName~SomeType"   # one project / one type / one test
dotnet build src/native/build.proj        # native C++ (shell extension, SSH askpass); needs VC++/ATL
.\update-loc.cmd                          # regenerate GitUI/Translation/English.xlf (runs a build first)
```

Build output goes to `artifacts/<Configuration>/` (see `eng/RepoLayout.props`), not next to the projects. The SDK is pinned in `global.json`; package versions live only in `Directory.Packages.props` (central package management).

## Architecture

One-way dependency chain: `GitExtensions.Extensibility` → `GitCommands` → `GitUI` → `GitExtensions` (exe). Never add a reference that points the other way (e.g. `GitCommands` must not reference WinForms/`GitUI`). `GitExtUtils` and `ResourceManager` are shared helpers; `src/plugins/*` hang off `GitUIPluginInterfaces` and are loaded via MEF; `src/native/` is the C++ Explorer shell extension. `tests/` mirrors `src/` (`tests/app/UnitTests`, `tests/app/IntegrationTests`, `tests/plugins/UnitTests`, shared `tests/CommonTestUtils`).

Typical action flow: a `Form` in `GitUI` → `GitUICommands` (runs commands *with* UI feedback, raises `RepoChangedNotifier`) → `Commands` (`GitCommands.Git`) builds a structured `IGitCommand` via `ArgumentBuilder` → `GitModule` (one per repo) runs it through `IExecutable`/`Executable` → output is parsed into models. `IGitCommand` declares `AccessesRemote` and `ChangesRepoState`, which `GitUICommands.StartCommandLineProcessDialog` uses to choose the dialog and decide whether to fire repo-changed.

Things that span several files and are easy to miss:

- **Threading:** WinForms plus vs-threading. Switch with `await ThreadHelper.JoinableTaskFactory.SwitchToMainThreadAsync()` before touching controls; never block with `.Result`/`.Wait()` (use `JoinableTaskFactory.Run`). Analyzer input lists are in `eng/vs-threading.*.txt`. Fix analyzer findings rather than suppressing them. `eng/BannedSymbols.txt` bans e.g. `MessageBox` and NUnit `ClassicAssert`.
- **Two settings worlds:** app preferences (`AppSettings`, stored in `GitExtensions.settings` XML) vs real git config (`*Settings` classes, `IGitModule.GetSetting`). Decide which one a value belongs to first.
- **DI:** `System.ComponentModel.Design.ServiceContainer`, populated by a `ServiceContainerRegistry.RegisterServices` in each of `GitExtensions`, `GitCommands` and `GitUI`; resolve with `GetRequiredService<T>()`.
- **Theming:** colors are `AppColor` values resolved through a CSS-based `Theme`; don't hardcode `Color` literals in UI code.
- **Translations:** UI strings are `TranslationString` fields; `English.xlf` is generated by `TranslationApp` via reflection. Never hand-edit `.xlf` files.
- **Public plugin API:** `src/app/GitExtensions.Extensibility/` is versioned (mirrored to the gitextensions.extensibility repo). Keep changes additive and deliberate. Prefix/suffix string members in shared libraries must be `public static` properties, not `const`, so values aren't inlined into plugin assemblies.

Deeper agent-oriented docs live in `.github/copilot-docs/` (start with `L0-foundations/gitextensions-primer.md` and `docs-index.md`, then follow a reading chain for the subsystem). Some cover flows like commit, rebase and the revision grid. Verify against the source, since a few details there are stale (e.g. `.github/copilot-instructions.md` says C# 13, but `Directory.Build.props` sets `LangVersion` 14.0).

## Conventions (enforced by build/CI)

- Files use CRLF line endings; follow `.editorconfig` and StyleCop (using order `System.*` first then alphabetical, no trailing whitespace, blank line after closing braces). File-scoped namespaces; newline before every opening brace; local functions go after a final `return;`, alphabetically.
- Nullable is enabled: use `is null` / `is not null`, avoid `!` (prefer `Validates.NotNull`), no `var` for primitives, prefer `new()` when the type is declared.
- All git operations go through `IGitModule` with unit tests asserting the built arguments; build args with `Commands`/`ArgumentBuilder`, never raw strings. Prefer `-z` (NUL-delimited) output, and split key/value lines on the first space only.
- Any UI string or control change requires `update-loc.cmd` and committing the updated `English.xlf`; CI fails if it's stale. WinForms controls use prefixes like `lbl`, `btn`, `txt`, `cbx`, `chk`, `rb`, `gbx`, `tlpnl`, `flpnl`, `lnk` (see `.github/ui_design_guidelines.md`).
- Tests: NUnit + NSubstitute + AwesomeAssertions (never `ClassicAssert`, Moq or MSTest attributes). Name tests `MethodUnderTest_should_do_x`. No Arrange/Act/Assert comments. Substitute `IExecutable`/`IProcess` so tests don't spawn `git`. Private members are reached through a class's `TestAccessor` (no xmldoc on those). `Verify.NUnit` `.verified.*` snapshots must be reviewed when they change. Fix flaky tests at the root cause; don't add `[Ignore]`.
- Comments explain *why*, not *what*; extract magic numbers and repeated string literals to named `const`s. Non-private APIs get XML docs (multi-line `<summary>`); don't add them to plain interface/abstract implementations.
- Commit messages follow Conventional Commits (e.g. `fix(diff): ...`). Note in the message when `GitExtensions.Extensibility/` is touched.
